- Cultivate can triage issues assigned to the bot in GitHub Issues, Linear and Jira: `mimir cultivate setup --tracker github-issues|linear|jira` (repeatable) installs the optional `tracker-poller` skill, writes the `tracker:` section of `worklink.yaml`, stores the Linear and Jira credentials in `compose.env` (`--linear-api-key-file`, `--jira-email-file`, `--jira-api-token-file` and their `-stdin` forms, or a plain `--jira-email`) and remembers the selection on later runs. Only threads whose latest activity comes from a trusted person reach the agent. Setup rewrites an unedited `worklink.yaml` when the tracker selection changes; a hand-edited file still needs `--force`.
- Worklink now rewrites builder-written closing keywords (for example `Fixes` or `Resolves` followed by an issue reference becomes `Refs`) on every leaf pull request Worklink opens, so only the tracker-linked `Closes` line closes an issue. Epic pull requests are written by the feature factory; once the factory completes and its pull request is verified, Worklink edits that pull request to add the same tracker line, remove Chainlink ids and apply the same rewrite. Because the whole epic body is model-written, the scrub covers all of it, including quoted commands and counts that match the Chainlink id. If the edit fails, the epic still moves to review and the operator gets a `factory_publication_degraded` notice naming the pull request and the reason. The tracker line closes the issue only through the tracker's own GitHub integration, which acts on a merge to the default branch, so an epic that targets a feature branch still relies on the `close_on_merge` backstop to close its issue.

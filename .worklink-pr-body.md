## Summary

Retire the generic per-file integrity ledger and its permanent-untrusted
ratchet. HOME reference reads rely on the unchanged protected write gate;
ordinary writes, framework publication, startup, and prompt/index reads no
longer consult or update `file-integrity.json`.

Retain the acceptance-required exception: explicit admin-installed skill
authority in `.mimir/skill-integrity.json`. This is skills-only installation
metadata, not a renamed generic ledger, and `skills/` has no trusted location
default.

## Behavior And Upgrade

- HOME read roots are `.mimir_builtin_skills`, `docs`, `memory`, `prompts`,
  `skills`, and `state`. All except `skills` are trusted/informational after
  canonical resolution, except `state/pollers`, which remains
  untrusted/active-ingest. Skills require explicit installation records.
- External feature-factory, benchmark, and any other `:rw` roots default to
  untrusted/active-ingest, including formerly recorded clean writes. Writable
  access and an old absolute-path trusted entry do not confer integrity.
- The existing source-repository and matching head-bound trusted-author PR lease
  exceptions are unchanged. Fetch-cache sidecar validation is unchanged; even
  approved fetched content remains untrusted/active-ingest.
- `/mimir-home/.mimir/file-integrity.json` is **LEFT IN PLACE AND IGNORED**:
  no migration and no runtime read/write, including at startup. The new document
  marks it obsolete. Operators may archive or remove it offline, but neither is
  required. Historical marks, epochs, and repair records are not authority.
- Old skill records are **not imported**. Existing skills are untrusted until
  an operator explicitly reinstalls from an approved source or reviews and
  records the existing installation offline using
  `record_admin_installed_skill_integrity(home, skill_root)`. Do not copy or
  rename the old ledger. Prefer preserving reviewed custom installations;
  forced reinstall can destroy custom edits and is not routine cleanup advice.
- The unchanged protected write gate is not a filesystem sandbox. Retirement
  removes per-file history rather than promising detection of arbitrary offline
  or subprocess changes. Live IFC and skill admin-operator restrictions remain.
